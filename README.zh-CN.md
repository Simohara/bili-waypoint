# CCB Auto：香港／海外节点优选

可安装文件：[dist/ccb-auto.user.js](dist/ccb-auto.user.js)。基于 CCB 2.1.0，保留原版的播放地址拦截、Worker、直播／番剧手动设置，新增功能用于普通视频页。

## 安装

1. 先关闭旧版 CCB，以及其他同时修改 B 站播放源的脚本，避免叠加拦截。
2. 在 Tampermonkey 管理面板新建脚本，将 `dist/ccb-auto.user.js` 的完整内容粘贴进去并保存；也可以用管理器的文件导入功能。
3. 刷新普通视频页。标题右侧出现约 196 × 26 px 的状态胶囊。第一次从视频首页导航进入已打开的网页时，也建议完整刷新一次，让 document-start Hook 安装到位。

## 默认行为

| 项目 | 默认值 |
| --- | --- |
| 自动检查 | 开启 |
| 触发频率 | 每观看 3 个视频 |
| 观看计数 | 页面可见，视频有效播放满 20 秒才计入；同一视频刷新或切 P 不重复计数 |
| 测速冷却 | 至少间隔 10 分钟，避免连续短视频导致频繁测速 |
| 卡顿检查 | 默认开启；连续缓冲约 2.5 秒后立即启动，不等待观看计数和常规冷却 |
| 卡顿限流 | 同一次卡顿只检查一次，重复卡顿检查至少间隔 90 秒 |
| HTTP 延迟上限 | 350 ms |
| 4K 速度目标 | 35 Mbps；若拿到的 4K 轨道码率更高，以视频加音频码率的 1.3 倍提高门槛 |
| 单次正常检查 | 3 个 1 字节 HTTP 延迟样本，中位数；一个 512 KiB 下载样本 |
| 可疑结果 | 以 2 MiB 样本复测，避免只凭很短的一次采样换源 |
| 节点不合格时 | 串行粗测允许节点，每个 256 KiB；按粗测排序用 2 MiB 复测并校验普通音频，直到取得 3 个达标备选或候选耗尽 |
| 节点切换 | 只在点击“切换并刷新”后应用 |

35 Mbps 是可调整的保守目标，B 站 4K 实际需要的带宽随视频和编码变化，不是官方统一硬门槛。此版本使用十进制 Mbps，按实际收到的字节和完整请求用时计算。

点击胶囊，在折叠的“设置”中修改检查视频数、延迟上限、4K 速度目标，或关闭自动检查、卡顿检测。也有“立即测速”和“取消测速”。测速仅在前台执行；常规周期检查要求至少有 5 秒缓冲，卡顿检查不受此限制。切视频、切 P、隐藏标签页会取消当前测速。

`2.2.0-auto.3`：卡顿或点击“立即测速”都会主动筛选备选节点，即使当前节点测速暂时正常，也可查看最多三个达标结果。常规周期检查仍只在当前节点不达标时扩大测速范围。结果列出地区、速度与 HTTP 延迟，默认选中第一名；可以改选第二或第三名，再点“切换并刷新”。合格节点不足三个时如实显示实际数量，不用失败节点补位。

卡顿判断结合 `waiting`、`stalled`、播放状态、播放进度和当前缓冲区间。短暂缓冲、暂停、后台、拖动进度和接近结尾均不触发；拖动结束后有约 2.5 秒宽限。仅有 `stalled` 事件但仍有充足缓冲，也不会启动测速。同一次卡顿不反复检查；最近 90 秒做过完整手动／卡顿选源时不重复扫描。

卡顿检测会自动开始测速并展示可切换节点，仍保留“切换并刷新”的批准步骤，不会自行刷新页面。

主动测速使用安装拦截前保存的原生 fetch，配合 `cache: no-store`，不附加会触发部分 CDN CORS 错误的防缓存请求头。已修改过的页面 fetch 不参与节点探测，防止多节点被统一改到当前节点。

## 刷新批准

发现不合格的当前节点并找到达标替代节点，或主动完成备选测速时，胶囊亮起温和的提示点，展开一个不遮罩页面、不会抢焦点的浮层，展示原节点问题（如有）、最多三个可选节点的成绩与以下按钮：

- **切换并刷新**：应用单选框中选中的节点，刷新，并尝试恢复播放进度和暂停状态。
- **稍后**：收起浮层；下次点击胶囊仍可查看。两分钟后建议过期，需要重新测速。
- **保持当前**：放弃本次建议。

脚本不会自动刷新。尚未批准的候选不会改写当前请求，也不会影响已创建 Worker。全部候选不合格时只提示失败，不推荐大陆节点。

选择保存在当前 B 站标签页的会话中，有效 24 小时；其他标签页的当前视频不会被该选择强制改源。通过原版 CCB 设置面板人工选择普通视频节点，会清除本标签页的自动选择。

## 标题旁显示什么

- **↓ 数值 Mbps**：来自当前视频自己的媒体分段下载，包括页面 XHR、fetch 和已成功注入的 Worker 请求。统计不额外下载第二份视频。
- **测 数值 Mbps**：当前没有新加载数据时，显示本视频最近主动测速结果；悬停可查看时间。
- **ms**：HTTP 请求延迟；主动探测用一字节请求完成时间，播放器观测用响应头到达耗时。它不是 ICMP ping。
- **—**：没有可靠样本，不用零值或虚构数据代替。播放器已缓存或暂停时没有持续下载是正常现象。

分段加载速度可能受到浏览器缓存、连接复用和播放器读取节奏影响，是最近一个分段的有效加载吞吐，不是网卡持续流量。视频首屏完全缓存、未能注入的播放器 Worker 或其他脚本接管请求时，实时分段数据可能暂不可见，主动测速仍会单独标识。

通常靠标题文本右侧放置，不把胶囊插入或改变 H1 文本；空间不足时靠标题下缘；滚出标题区域、全屏和网页全屏时隐藏。默认胶囊不展开，只有查看详情或产生换源建议时显示浮层。

## 节点来源

自动优选只读取仓库 `data/cdn.json` 的 `香港`、`海外` 两个数组：

https://raw.githubusercontent.com/Kanda-Akihito-Kun/ccb/main/data/cdn.json

不使用此前较旧的 GitHub Pages 节点数据。构建内置的仓库快照来自提交 `2534fd087338047a5938d12c9fe0448b4a9b2bf7`，香港 12 个、海外 4 个。

测速时会尝试更新仓库数据（每小时最多一次）；访问失败时使用有效仓库缓存，最后使用内置仓库快照。折叠设置中提供节点来源链接，悬停可查看来源和日期。香港／海外是仓库的分组，不等同于独立验证服务器物理位置。

## 验证与实现

- 核心策略：`src/auto-core.js`。
- 上下文识别、真实分段校验、调度和批准：`src/auto-runtime.js`。
- 页面与 Worker 观测：`src/telemetry.js`。
- 卡顿检测：`src/stall-watcher.js`。
- 界面：`src/widget.css`。
- 构建：`node scripts/build.cjs`。按固定上游 SHA-256 校验并检查每个集成位置；上游变动时会停止构建，要求重新检查。
- 测试：`node tests/run.cjs`。需要 Playwright 和 Chrome；当前脚本中的依赖路径按本机环境配置。
- 测试结果：`dist/test-results.json`。
- 界面截图：`dist/preview-compact.png`、`dist/preview-dark.png`；使用本地受控页面，数值为测试数据。

已在真实 Chrome 的受控页面验证：URL 和分 P、严格节点池、响应长度和错误页拒绝、播放器 fetch、真实 Blob Worker 与私有通道、低速复测和节点筛选、刷新批准、恢复进度、SPA 取消、自动观看计数和可编辑设置。

卡顿验证还覆盖持续缓冲触发、短暂缓冲恢复、暂停、拖动进度、后台、缓冲充足、同一事件去重、90 秒限流和关闭卡顿检测。界面只保留当前节点、速度、HTTP 延迟、状态和节点选择；解释段落、观看计数等不再占用主面板。

另外在匿名 Chrome 的真实 B 站来源下，海外 `mirrorcosov`、香港 `cn-hk-eq-01-01` 的 1 字节与 512 KiB 请求均成功返回有效 206，验证了原生浏览器跨域读取；结果见 `dist/live-cors-results.json`。这是各一次小样本，不是全部节点的稳定排名。

这些自动化验证没有接管你的登录浏览器，也不等于已在你的 Tampermonkey、账号、代理和当前播放器版本中完成实播验收。安装后先观察一个视频；打开浮层可主动检查并查看明确错误。浏览器不允许读取分段响应或 CORS 拒绝时，该节点不会被误认成高速赢家。
