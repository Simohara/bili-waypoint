# 驿程：香港／海外节点优选

可安装文件：[dist/yicheng.user.js](dist/yicheng.user.js)。从 CCB 2.1.0 分出（原版脚本收在 `vendor/ccb.js`，只有节点列表仍取自上游），保留原版的播放地址拦截、Worker、直播／番剧手动设置，新增功能用于普通视频页。

## 安装

1. 先关闭旧版 CCB，以及其他同时修改 B 站播放源的脚本，避免叠加拦截。
2. 打开 [安装链接](https://raw.githubusercontent.com/Simohara/bili-waypoint/main/dist/yicheng.user.js)，在 Tampermonkey 的安装页点“安装”；以后按版本号自动更新。也可以在管理面板新建脚本，粘贴 `dist/yicheng.user.js` 的完整内容。Chrome / Edge 需要先在扩展详情里打开“允许用户脚本”。
3. 刷新普通视频页（海外访问时跳转到的 `/zh-Hans/video/` 这类带语言前缀的地址同样生效）。标题右侧出现高 28 px 的状态胶囊，点开是“驿程”浮层。第一次从视频首页导航进入已打开的网页时，也建议完整刷新一次，让 document-start Hook 安装到位。

## 默认行为

| 项目 | 默认值 |
| --- | --- |
| 自动检查 | 开启 |
| 触发频率 | 每观看 3 个视频 |
| 观看计数 | 页面可见，视频有效播放满 20 秒才计入；同一视频刷新或切 P 不重复计数 |
| 测速冷却 | 至少间隔 10 分钟，避免连续短视频导致频繁测速；点“取消”停止测速或保存设置后，下一次自动检查也推迟 10 分钟 |
| 卡顿检查 | 默认开启；连续缓冲约 2.5 秒后立即启动，不等待观看计数和常规冷却 |
| 卡顿限流 | 同一次卡顿只检查一次，重复卡顿检查至少间隔 90 秒，从上次扫描结束时算起；扫描没找到可用节点时，卡顿测速暂停 10 分钟 |
| HTTP 延迟上限 | 350 ms |
| 速度目标 | 35 Mbps；若拿到的 4K 轨道码率更高，以视频加音频码率的 1.3 倍提高门槛；没有 4K 轨道时，门槛取最高轨道码率的 1.3 倍，不超过 35 Mbps |
| 单次正常检查 | 3 个 1 字节 HTTP 延迟样本，中位数；一个 1 MiB 下载样本；文件短于样本时按文件实际长度测 |
| 可疑结果 | 以 2 MiB 样本复测，避免只凭很短的一次采样换源 |
| 节点不合格时 | 串行粗测允许节点，每个 256 KiB；按粗测排序，前 5 名一定用 2 MiB 复测，之后粗测低于门槛一半的不再复测；复测同时校验普通音频，取最快的 3 个达标备选。当前节点达标时，备选至少要达到设置的速度目标 |
| 扫描没找到 | 周期检查不弹出浮层，胶囊路线图标的末站变成空心；之后 30 分钟（3 个冷却）内不做周期检查，10 分钟内不做卡顿测速（手动和卡顿扫描没找到也算）；之后找到节点或当前节点达标即解除 |
| 节点切换 | 只在点击“改走 … 并刷新”后应用 |

35 Mbps 是可调整的保守目标，B 站 4K 实际需要的带宽随视频和编码变化，不是官方统一硬门槛。此版本使用十进制 Mbps。吞吐按实际收到的字节和响应头到达之后的传输用时计算，不把首字节等待算进去；HTTP 延迟仍按完整请求用时。

点击胶囊展开浮层：底部“重新巡站”立即测速，测速中这个按钮变为“取消”；折叠的“设置”中可修改检查视频数、延迟上限、目标 Mbps，或关闭自动检查、卡顿检测（关闭自动检查时卡顿检测一并停用，勾选框变灰）。测速仅在前台执行；常规周期检查要求当前播放位置之后至少有 5 秒缓冲，并且最近 2 秒播放器没有在下载分段，避免测到的只是剩余带宽；卡顿检查不受此限制。切视频、切 P、隐藏标签页会取消当前测速。在其他标签页改的设置，切回本页时生效；本页设置表单开着时，表单也换成新值。

`2.2.0-auto.4`：按 2026-11-03 审查修复测速偏差、端口、Worker 兼容和调度问题。带端口的 mcdn 地址改用 `backupUrl` 里的 upos 地址探测候选节点；20 分钟后的元数据刷新会重新请求播放地址。原版遗留的 Worker/Blob 问题一并修复：数据 Blob 不再被改写，`instanceof`、Worker 子类和 Worker 里的相对地址恢复正常；开启改源时，弹幕防挡蒙版不再被改到所选节点。

`2.2.0-auto.3`：卡顿或点击“重新巡站”都会主动筛选备选节点，即使当前节点测速暂时正常，也可查看最多三个达标结果。常规周期检查仍只在当前节点不达标时扩大测速范围。结果列出地区、速度与 HTTP 延迟，默认选中第一名；可以改选第二或第三名，再点“改走 … 并刷新”。合格节点不足三个时如实显示实际数量，不用失败节点补位。

卡顿判断结合 `waiting`、`stalled`、播放状态、播放进度和当前缓冲区间。短暂缓冲、暂停、后台、拖动进度和接近结尾均不触发；拖动结束后有约 2.5 秒宽限。仅有 `stalled` 事件但仍有充足缓冲，也不会启动测速。同一次卡顿不反复检查；上次完整手动／卡顿选源结束后 90 秒内不重复扫描。元数据还没取到时，卡顿窗口继续等待，取到后再测速。

卡顿检测会自动开始测速并展示可切换节点，仍保留“改走 … 并刷新”的批准步骤，不会自行刷新页面。

主动测速使用安装拦截前保存的原生 fetch，配合 `cache: no-store`，不附加会触发部分 CDN CORS 错误的防缓存请求头。已修改过的页面 fetch 不参与节点探测，防止多节点被统一改到当前节点。

## 刷新批准

发现不合格的当前节点并找到达标替代节点，或主动完成备选测速时，胶囊路线图标的末站变成朱色，并展开一个不遮罩页面、不会抢焦点的浮层：当前站后面直接写出它的问题（如“低于目标 35”“不在候选池”），下面列出最多三个可选节点的地区、HTTP 延迟、速度和相对当前的倍数。按钮如下：

- **改走 … 并刷新**：按钮上写着目的地，即路线上选中的那一站；盖下“换”字驿印后刷新，并尝试恢复播放进度和暂停状态。
- **×（收起）**：收起浮层；下次点击胶囊仍可查看。两分钟后建议过期，需要重新测速。
- **保持当前**：放弃本次建议。

脚本不会自动刷新。尚未批准的候选不会改写当前请求，也不会影响已创建 Worker。全部候选不合格时只提示失败，并按原因汇总（例如“HTTP 403 ×15”），不推荐大陆节点。

选择保存在当前 B 站标签页的会话中，有效 24 小时；其他标签页的当前视频不会被该选择强制改源。在原版 CCB 设置面板人工选择普通视频的节点或地区（在直播页或其他标签页操作也算），之前批准的自动选择即失效。

## 标题旁显示什么

- **数值 Mbps**：来自当前视频自己的媒体分段下载，包括页面 XHR、fetch 和已成功注入的 Worker 请求；只采信至少 256 KiB 的分段，速率不含首字节等待。统计不额外下载第二份视频。当前没有新加载数据时，显示本视频最近主动测速结果；悬停可查看是哪一种以及测速时间。
- **路线图标**：测速时显示“n/15 巡站中”，图标里的进度条跟着走；有换源建议时末站变朱色；扫描没找到可用节点时末站变成空心。
- **ms**：HTTP 请求延迟；主动探测用一字节请求完成时间，播放器观测用响应头到达耗时。它不是 ICMP ping。
- **—**：没有可靠样本，不用零值或虚构数据代替。播放器已缓存或暂停时没有持续下载是正常现象。

分段加载速度可能受到浏览器缓存、连接复用和播放器读取节奏影响，是最近一个分段的有效加载吞吐，不是网卡持续流量。视频首屏完全缓存、未能注入的播放器 Worker 或其他脚本接管请求时，实时分段数据可能暂不可见，主动测速仍会单独标识。脚本不改写任何 Blob。页面用 blob: 地址启动经典 Worker 时，从同一个 Blob 重建一份：先装观测代码，再把页面代码作为独立脚本加载，`self.location`、严格模式和报错位置都和原来一样。默认源下，普通地址的 Worker、模块 Worker 和 data: Worker 原样放行；开启原版改源时，同源的普通地址 Worker 和模块 Worker 也会被包装，里面的相对地址仍按原脚本地址解析。模块 Worker 不接入观测。

通常靠标题文本右侧放置，不把胶囊插入或改变 H1 文本；空间不足时靠标题下缘；全屏和网页全屏时隐藏；滚出标题区域时胶囊隐藏，已展开的浮层移到右上角。默认胶囊不展开，只有查看详情或产生换源建议时显示浮层。

## 节点来源

自动优选只读取仓库 `data/cdn.json` 的 `香港`、`海外` 两个数组：

https://raw.githubusercontent.com/Kanda-Akihito-Kun/ccb/main/data/cdn.json

不使用此前较旧的 GitHub Pages 节点数据。构建内置的仓库快照来自提交 `2534fd087338047a5938d12c9fe0448b4a9b2bf7`，香港 12 个、海外 4 个。

测速时会尝试更新仓库数据（每小时最多一次）；访问失败时使用有效仓库缓存，最后使用内置仓库快照。原版设置面板在没有缓存且仓库访问失败时，同样用内置快照列出地区和节点。折叠设置中提供节点来源链接，悬停可查看来源和日期。香港／海外是仓库的分组，不等同于独立验证服务器物理位置。

## 验证与实现

- 核心策略：`src/auto-core.js`。
- 上下文识别、真实分段校验、调度和批准：`src/auto-runtime.js`。
- 页面与 Worker 观测：`src/telemetry.js`。
- 卡顿检测：`src/stall-watcher.js`。
- 界面：`src/widget.css`。
- 构建：`node scripts/build.cjs`。按固定上游 SHA-256 校验并检查每个集成位置；上游变动时会停止构建，要求重新检查。
- 测试：`node tests/run.cjs`。需要 Playwright 和 Chrome；当前脚本中的依赖路径按本机环境配置。
- 测试结果：`dist/test-results.json`。
- 界面截图：`dist/preview-compact.png`、`dist/preview-dark.png`；使用本地受控页面，数值为测试数据。

已在真实 Chrome 的受控页面验证：URL 和分 P、严格节点池、响应长度和错误页拒绝、播放器 fetch、真实 Blob Worker 与私有通道、低速复测和节点筛选、刷新批准、恢复进度、SPA 取消、自动观看计数和可编辑设置。

卡顿验证还覆盖持续缓冲触发、短暂缓冲恢复、暂停、拖动进度、后台、缓冲充足、同一事件去重、90 秒限流和关闭卡顿检测。界面只保留当前节点、速度、HTTP 延迟、状态和节点选择；解释段落、观看计数等不再占用主面板。

另外在匿名 Chrome 的真实 B 站来源下，海外 `mirrorcosov`、香港 `cn-hk-eq-01-01` 的 1 字节与 512 KiB 请求均成功返回有效 206，验证了原生浏览器跨域读取；结果见 `dist/live-cors-results.json`。这是各一次小样本，不是全部节点的稳定排名。

这些自动化验证没有接管你的登录浏览器，也不等于已在你的 Tampermonkey、账号、代理和当前播放器版本中完成实播验收。安装后先观察一个视频；打开浮层可主动检查并查看明确错误。浏览器不允许读取分段响应或 CORS 拒绝时，该节点不会被误认成高速赢家。
